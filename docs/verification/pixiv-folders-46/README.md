【经验层】

- 架构决策与理由：使用根登记＋每目录作品库以保持“作品是直接子项”的现有读取契约；应用内位置登记仅负责重定位，作品详情不双写为第二份权威记录。整体文件夹回收独立建操作记录，保留子库和身份，避免沿用作品级恢复丢失目录关系。
- 接口/行为契约：workId用于在线身份，folderId/libraryId定位副本，operationId定位任务和恢复；UI、扫描、队列、删除都必须区分，混用会出现重复副本被吞或取消/删除错对象。两组默认策略均提示，但已经明确点击复制/移动时不再次询问动作类型。
- 根因链：打包打开后目录变文件→旧来源判定漏pixiv_download→走非托管目录兜底→图片/ZIP无封面而目录可命中cover→修正来源和外层失败短路，真实三形态测试通过。无缓存记录不能证明入口没被调用。
- 不要再走的路：不能只补长按外观而让选择操作仍从图集_items取条目；不能用同名存在当作完整内容；不能将损坏/只读数据库删除重建；不能给ZIP暂存使用归档后端不识别的最终扩展名；不能在测试fake-async里用无限pump等待真实磁盘IO。
- 技术约束：【来源：代码与故障注入测试】只有目标文件与目标记录都提交后才允许清源；未知源新增文件、摘要不符时停止清源。恢复要区分本次操作已经发布的目标和开始前已有副本。【来源：用户明确要求】只允许debug/profile，禁止隐式卸载和未经同意删除设备数据。

## 最终行为

- 首页推荐overview有限前分区完整排布，末分区收藏仍懒加载，消除已复现的缺列缓存负校正。详情来源相互独立：当前作者横排、作品级Pixiv相关推荐、关注后作者推荐不会互相替代。
- 在线评论预览4条根评论；初读limit4、展开单批20；超返与回复保缓存、offset按原始数。等待最多4槽；相邻非活跃详情不发自动请求。
- 设置→浏览→在线的“作者作品预览数量”与“相关推荐每批数量”默认5，各自范围1..30／1..18；旧配置／导入缺值补5、坏值补5，不继承陈旧内存。保存触发displaySettingsVersion，当前详情维持图片／评论与外层滚动对象，不重读详情。
- 作者横排补缺使用profile ID快照与最多5ID小批，有限自动预算；各图120dp高及48dp爱心，点击图进入同作者预览会话、点击爱心走平台收藏。未知状态只在点击时读取。
- 底部推荐首次可见才请求作品级recommend/init（明确传当前批数），保服务器顺序和nextIds；超过所选数量的数据保缓冲。末尾上拉120dp读一批，Clamping与Bouncing实际手势均验证，每次拖动最多一批，保错误重试／显式加载。过滤空批有游标进度，不自动耗完整队列。
- 关注写入确认成功后才读取GET /ajax/user/{uid}/recommends并打开圆角主题面板“发现更多作者”。5位作者×最多3图、横滚卡、独立关注按钮和每图爱心；推荐失败不会撤销已确认关注，关闭后忽略晚回包。收藏与详情动作每次执行都校验owner／账号／活动路由，包含账号变化但尚未重建的同帧边界。
- 多页在线图库作者头像旁提供收起按钮；收起为144..240dp首图contain封面，点封面再展开。使用原纵向ScrollController及局部锚点；正常末页→详情保持一条sliver流，没有额外idle吸附。收起隐藏推荐但保已读feed缓存，评论页底拉动不读隐藏推荐；展开后只有滚到推荐位置才读取。

## 调试过程中修正

- 数量变化替换feed后旧可见触发器已触发，导致新feed未读取：trigger key加入feed实例身份，实际设置修改回归验证同一外ScrollPosition和一次detail read。
- 面板FeedbackHost的StackFit.expand先撑满952dp，内部480dp约束失效：有限SizedBox移到宿主外层，四个截图矩阵实际测375×480，无溢出。
- 同帧账号／owner变更不能只依赖上一帧actionsEnabled：compact组件新增动态owner回调，入口与每次异步继续前核对；独立面板同帧旧按钮／图回调零读写与零打开。
- 关注期间刷新使旧结果失效但也跳过busy释放：写操作保忙锁直到自己finally释放，旧结果不打开面板，刷新后的按钮恢复可点；新增真实在线用例通过。
- 早期主测试失败包括异步回调expect与pumpAndSettle冲突（改同步断言）、懒加载作者栏未挂载就ensureVisible（改真实滚回）、短详情在按钮视口内已可见推荐（改推荐确实在视口外夹具）。并行shell／设置／卡片正在编辑时编译未进入测试的轮次不算通过；最终稳定源码结果如上。

## 外部证据与实际限制

推荐接口使用固定第三方公开实现与严格离线adapter验证。关注推荐[固定ppixiv源码](https://raw.githubusercontent.com/ppixiv/ppixiv/200f4ffcec8f8c2ac160c5bc8109297bd8ca2f44/web/vview/sites/pixiv/data-sources/discover-users.js)明确GET参数及recommendUsers/users/thumbnails.illust三容器；不把discovery其它字段猜为成功。匿名Pixiv web_fetch返回TypeError: fetch failed，未取得当前真实账号在线200，接口真实数据需后续设备／账号环境验收；错误独立显示，不用作者profile替代成功。

关注面板截图用空URL的真实生产placeholder核验布局，不假造线上图片。图库截图用明确离线内存图核验自然比例／锚点，均为Flutter引擎截图，包含msyh与MaterialIcons真实字体。

同一当前作品加载／展开／收起维持滚动对象；现有Pager完整切换作品会重建详情，返回会重新读limit4评论，此次没有宣称跨完整切换永久保持状态。短内容折起后最大滚动范围缩小，Flutter可能自然clamp offset到0；850dp锚点夹具能保header200dp与同一评论状态，1000dp短夹具的自然clamp如实记录。

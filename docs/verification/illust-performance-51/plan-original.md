# 51 · 插画页滚动与阅读入口性能优化

## 任务目标

在保留插画完整显示、文件夹管理、多选、封面自愈和无障碍功能的前提下，消除进入插画页及滚动过程中的同步 I/O、冗余后台补齐和图片字节压力，减少语义树更新开销；单独修复同一次操作路径中打开阅读器触发的全量历史查询。

本计划基于 50 号已经完成的离线诊断。调研不是留给执行者重做的任务；执行前补采用于建立同版本、可比较的实施基线。

## 当前理解的用户意图

用户从主页进入画集/插画页，往复滚动到底和回顶部，中间点开一张插画返回后继续滚动，希望整体顺畅。用户手机有 root，并授权了一些无障碍服务；修复要在这些能力保留的环境下有效。

用户要求综合分析后给出优化/修复计划，本侧会话只交付文档和分析附件。缓存继续统一保存在应用内目录；下载目录、作品原图和数据库记录不能作为“缓存清理”的牺牲对象。

## 不执行的内容

- 不修改 AI 气泡计划，不重写 Pixiv 目录复制/移动/删除、下载通知或后台下载保活。
- 不卸载、不清理应用数据、不迁移用户目录、不改作品文件或数据库 schema。
- 不关闭无障碍服务，不把整页包进 ExcludeSemantics，不通过少显示作品、裁图、降低列表功能来达标。
- 不改滚动物理、替换瀑布流库、强制降到 60 Hz，不盲目增大 imageCache 或全量预解码。

## 诊断思路与关键结论

详见 50 号报告及附件。决定本计划方向的事实：

1. 帧 276 的 76.995 ms Vsync 等待区间里，79 个 CPU 样本中 76 个经过同步目录读取；Future 声明没有消除其 UI 阻塞。
2. `flushSemantics` 占 35.83% 含子调用采样，42 次完整语义事件超过 8.333 ms。Flutter 3.41.6 在画面提交后再 flushSemantics，单看 build 柱会漏掉这部分 UI 工作。
3. 卡片已经降采样，但 managed 封面仍走整份字节读入与 ImmutableBuffer 拷贝。已有缩略图缓存未接入插画展示；provider 构建时仍 statSync。
4. 当前全量封面预解析和尺寸/页数补齐缺少统一的滚动/页面生命周期调度；已有下载漫画页具备 140ms idle 恢复先例，可复用其行为原则。
5. 打开阅读器时，帧 766 的 build 61.975 ms；`HistoryManager.find` 为查单项先 getAll。target 已有主键，可消除不必要的全量查询。

这些事实不意味着“所有慢帧都是语义/GC”或“把函数改成 async 就完成优化”。需要以正确时间区间、同设备分场景记录验证。

## 具体执行步骤

### 1. 接手边界与可比基线

执行者核对主会话当前代码和同文件改动，更新本计划状态为“执行中”。阅读交接经验版 §26、§27，尤其是特权封面与曾删除的常驻预热。它们的历史 release 建议服从当前 AGENTS 的 debug/profile 限制。

保存原始两份记录及 SHA-256，不覆盖。本次分析附件可以复算，但不是当前修复版的实测。

同一台设备、profile 模式、相同库内容/排序/列数/显示字段/刷新率和无障碍配置，分三条录制：进入页面至首批封面稳定；首屏稳定后连续往返滚动至少 30 秒；打开同一插画并返回后继续滚动。每条至少 3 次，报告中位数并保留各次数据。冷态使用正常重启或专用测试数据环境，不清空用户应用数据；暖态在同一数据版本下复用缓存。

记录设备型号、显示刷新率、应用与 Flutter 版本、温控/电量及录制选项。若确有无障碍服务，日常配置为主验收；仅在用户自行同意切换时做临时开/关对照，复测后恢复，不能把关闭状态作为唯一通过条件。

使用轻量帧/队列计数和少量阶段标记；详细 tracing 单独用于定位，不开启所有增强跟踪后拿结果与轻量基线直接比较。新增计数不写作品路径/账号等敏感数据，不逐帧落盘。App 生命周期、页面切换和加载代次要有可观测标记。

### 2. A：独立加载插画数据，移除 UI 同步扫描

- 当目标视图是插画时，直接加载插画所需的托管下载数据，不串行等待图集远程可用性探测及无关目录的封面预热。图集/远程页仍在真正切换过去时执行原流程。来源模式“仅本应用/仅原应用/两者”继续生效，不能只扫新的 Pixiv 根而漏掉旧混合根中的插画。
- 把本链路上的目录 `existsSync/listSync` 改为真正异步 I/O；保留空结果或读取失败时尝试特权通道的既有规则、`followLinks: false` 和返回结构。列表 build 与 itemBuilder 不得触发文件探测、SQLite 打开或全量 JSON 解析。
- SQLite 快照读取/大量 JSON 规范化/同步 ZIP 中央目录解析若在 UI 上超出预算，放入受控 worker；传可发送的路径/数据和设置快照，worker 自己开关数据库，不能跨 isolate 传活跃 sqlite 句柄、Widget 或 ui.Image。平台权限回退仍由可用的通道入口负责，不能假设普通 isolate 直接具备所有平台通道能力。
- 复用已有安全数据库快照读取，保持活跃下载写入、WAL、source mode 的一致性，不新增随意复制活跃 db 的路径。
- 为一次数据版本合并重复加载，保留已完成快照用于普通返回/纯滚动；下载完成、复制移动删除、目录迁移、权限/来源配置变化触发失效。手动刷新仍强制重读，外部改动可通过手动刷新发现。
- 多次刷新使用递增 generation；旧结果只能完成自身资源释放，不得覆盖新列表。已有列表刷新时保留内容，不回退整页遮罩。

### 3. B：统一可见项封面、宽高和页数补齐

由页面拥有一个可取消/可暂停的有限队列，合并 `_prefetchIllustCovers` 与 `_resolveIllustSizes` 对同一项的工作，或让二者共享同一排程与 in-flight 表。

- 用当前布局的可见索引范围及最多邻近一屏确定优先级；瀑布流高度不齐，不能简单用 offset 除固定卡高估算。可用 delegate 的布局范围回调收集范围，不能在布局回调里直接 setState。
- 初始可见项优先；封面/尺寸解析总并发起点为 2，昂贵缩略图生成为 1。数字可按 A/B 调整，但必须有明确上限；不同时运行两套各自无上限的队列。
- 仅主纵向滚动（depth=0）的开始/拖拽/惯性状态控制暂停；嵌套标签横向滚动不误暂停整页。不依赖 FAB 是否显示来决定调度是否工作。
- 活跃滚动时不启动新的特权源读取、全图缩略图生成和全量页数扫描；已缓存封面照常显示，现有 Image 的滚动感知机制照常工作。无法安全取消的在途任务允许完成并妥善释放，但结果需经过版本校验。
- 停止后约 140ms 恢复可见项；用户再次滚动立即取消 idle timer，排队任务不丢失、不重复。离开该页、打开阅读器覆盖它、应用进入后台时暂停新工作；dispose 取消尚未启动项并释放监听。该调度只管理列表装饰信息，不暂停用户后台下载队列。
- 每项 key 使用位置身份及内容版本：同一 Pixiv ID 在不同自定义文件夹的副本不能互相覆盖。尺寸、页数、负缓存和 provider 采用同一失效边界。
- 已有元数据时不读文件；未启用页数字段不数页，打开字段后补齐；单图页数为 1，ZIP 排除封面，旧目录/特权源保持原规则。不要把短期权限失败永久记成零页/无封面。
- 按实际变更局部发布封面/尺寸；没变化不发通知。尺寸导致卡高改变时合并到 idle 提交并保持可见锚点，不能每张图完成就把全页重新排序或跳回顶端。

### 4. C：让插画真正复用应用内缩略图

保留统一封面缓存入口，先解析可用封面，再异步查找或生成适合显示尺寸的衍生缩略图。不得在 build 中调用旧 `CoverThumbnailCache.displayPathForCover` 等同步 stat 接口。

- provider 工厂只消费已准备好的路径、版本及尺寸，纯内存生成 key；源 fingerprint 在扫描/解析阶段异步获取，不在每次 itemBuilder 中 stat。
- 尺寸根据列宽 × DPR × 现有清晰度余量计算，向上归入有限档位（建议初始 384/768/1536px；超出档位时保留原图降采样路径），并与原图实际尺寸取合理上限。不为不足宽度的小图强制放大。档位策略为实现初值，须通过 1/2/多列及高 DPI 视觉验证。
- 超长图应增加像素面积/长边保护，或使用按显示区域需要的缩放尺寸；保持完整显示，不能以裁掉内容来控制内存。真实宽高由原记录/原封面头读取，不能用缩略图元数据反向篡改作品信息。
- 缩略图键包含封面身份、源版本、尺寸档位和生成算法版本。所有衍生文件只写 `<App.dataPath>/local_library_cache/covers/thumbs`，不得写用户自定义下载目录或迁移目标。
- 同 key 生成共享 Future，有限并发；生成前后校验源版本，源在处理中改变则放弃旧结果并重新排队。先写唯一临时文件、成功后发布，失败/取消不暴露半图。复用已有缓存配额/清理接口并补足该子目录的统计；仅清理可再生缩略图，不触及原图、download.db、历史库。旧缓存按版本回退重建，不能靠清空全部用户缓存“解决”。
- 普通应用内部、已确认可直接读取的缓存文件可以经文件缓冲 provider 加载，减少 Dart 整份原字节驻留；外部 root/Shizuku 文件继续走权限安全解析/读取。改动在 manager/专用本地封面 provider 层实现，卡片不绕过 manager。
- 本地磁盘封面 provider 若仍需走 BaseImageProvider，使用已有 `cacheRawBytes=false` 钩子；保留 ImageCache 中按实际尺寸解码的图像复用。不能改基类默认值影响阅读器、远程、压缩包全部图片。
- 缓存不存在时先保留当前可用图或占位，由同一受控队列补齐；惰性 provider 的 cache miss 也必须接入该队列，不能从另一条 loader 绕过滚动/页面生命周期门控；生成失败仍可走原封面限尺寸路径，用户停下后必须最终显示图。清理/源变更后的 evict 要针对同一内容版本及 ResizeImage key，避免缓存生成了 UI 仍破图或显示旧图。
- 源文件移动、复制、替换、根迁移后，旧任务不回写新项；衍生缓存继续在应用内部，不跟随内容目录迁移。复用现有主线迁移事件，只加失效通知，不重写迁移事务。

### 5. D：缩小重建范围并保留可访问操作

- FAB 的 `_scrollInteracting` 变化用局部 ValueListenable/独立 StatefulWidget 响应，不能只为透明度整页 setState。
- 筛选结果、信息 spans、文件夹显示信息按输入列表版本、筛选词、标签、folder ID、显示设置缓存；数据变化显式失效，不单纯依赖原地 List 的 identity。
- 用条目位置身份设置稳定 Key，排序/筛选时提供对应索引映射。保留同作品在两个文件夹各一份、多选和卡片尺寸补齐后的状态，不用纯作品 ID 当所有副本的 key。
- 先用 SemanticsTester/调试探针量出每卡和可见区节点数。去掉选择高亮、装饰图标及无独立操作意义图片的冗余语义；给图片区“阅读”和文字区“详情/管理”提供明确标签及操作，长按多选、selected、计数和滚动索引必须保留。
- 不使用全局 ExcludeSemantics、不盲目关 addSemanticIndexes，不把有两个不同操作的卡片 MergeSemantics 成一个不可区分入口。只改实测存在的重复节点/更新，保留读屏可理解的标题/作者/位置。
- 对 `cacheExtent` 250dp、半屏、一屏做同样数据的 A/B，选择满足快速滚动不长时间空图的最小稳定值；默认值在执行回写中给出理由。Sliver 已自带 RepaintBoundary，不重复逐卡堆层；若发现特定返回动画绘制热点再局部处理。

### 6. E：单项历史按主键查，避免入口全表加载

修改 `HistoryManager.find/findSync`：先保持来源可见性规则，再直接复用 `_findInDb` 的参数化 target 查询。单次查找最多主库和副库两次，不为了判断存在而构造全量成员缓存；已有 target 主键，无需迁移或新增索引。

严格保留原有空/未初始化返回、target 匹配、主库优先/副库回退、原应用来源过滤和历史写入行为。不要把 `getAll` 的“按时间合并”规则无意套进 `find`；如发现既有行为不一致，单独记录，不在性能修复里擅改语义。

阅读器的 `late final history` 可继续每个页面实例解析一次，但 build 中不得触发全库读取。`findManySync`、历史页排序和所有迁移逻辑不为本步骤顺带重写。

### 7. 分工作包回归与真机闭环

先测历史单项查询、调度器、缓存版本及失败恢复，再做插画卡片/列表的真实 Widget 测试，最后复测 profile。已有相关测试包括 `local_library_illust_*`、`illust_cover_size_test.dart`、`illust_archive_page_count_test.dart`、`local_cover_cache_test.dart`、`pixiv_folder_cover_integration_test.dart` 和历史/来源切换测试；新增断言要覆盖真实行为，不能只比较常量或 grep 代码。

各包记录前后指标与验证结果，不能一次改完后仅凭“总测试通过”声称不卡。与主会话共用文件时先核对最新实现；同步存储接口改动要覆盖非插画调用者的契约回归。

## 风险或注意事项

- **统计口径**：导出 startTime=buildStart、elapsed 从 vsyncStart 开始；语义更新在提交画面后。时间对齐参考 50 号脚本，不能把相邻帧误归因到本帧。
- **特权访问**：应用内缓存的直接读取与外部源的权限回退必须分开。裸 FileImage 接外部目录曾导致整片破图。
- **调度**：限并发和 idle 不等于后台线程；同步解析仍会阻塞当前 isolate。可取消任务不要拿全局 ImageCache.clear 当取消方法。
- **缓存**：源版本变化、手动刷新、权限恢复、负缓存 TTL 都是契约；只依赖目录 mtime 可能漏掉目录内文件替换，需要数据版本/实际封面 stamp 或强制刷新兜底。
- **缩略图**：首次生成仍有解码编码成本；必须限制启动时机。固定 720px、直接写 PNG、statSync 的旧接口不满足本计划，需异步、版本化与原子发布后才能复用。
- **无障碍**：35.83% 是重叠 CPU 采样占比，不能用它承诺 35.83% 总性能提升。服务具体身份未知，节点优化须保留操作语义并在真实配置复验。
- **共享范围**：历史管理、存储访问和图片 provider 被多个页面使用；局部接口/可选策略优先，不改全局默认行为。
- **数据安全**：只允许 debug/profile。若用户另行安排安装，验证产物路径和显式设备 ID，保持数据；禁止卸载、清空数据及 release。

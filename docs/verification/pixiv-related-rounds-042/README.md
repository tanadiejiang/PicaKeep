# 042 · 默认按 Pixiv 返回显示一轮，并由手势继续推荐

用户明确修正040的底部默认5：新增“由Pixiv返回”并设默认，每轮看完以后才由末尾上拉请求下一轮。作者横排的默认5保持独立。实现与定向离线验证已完成；多图详情纠正另见[043](../../../Z-plan/新需求-主线-第十九轮/043-计划-Pixiv多图先看图与详情面板衔接纠正.md)。

## 当前行为

- 设置→浏览→在线→相关推荐每轮数量：默认“由Pixiv返回”，另有“自定义数量”1–18。存储新模式索引170，原169数字保为最后手动值。旧数组缺模式迁移pixiv，导入不会继承内存残留custom，作者168默认5、旧036队列数量默认关闭及167保留位不变。完整设置证据见[设置记录](settings-record.md)。
- 推荐区真正进入可见范围才请求首轮；默认显示本轮全部有效回包，7／23项不会截成5或18张；下一轮之前不自动读nextIds。UI仍为两列懒加载卡片，收藏、打开详情及屏蔽规则沿用原实现。
- 看完本轮，到实际页底继续上拉120dp，或点“上拉或点击，再推荐一轮”，才继续一轮。Clamping及Bouncing两种实际手势通过，一次拖动最多一轮。仅跳到末尾、布局或图片衔接动画不会自动新推荐。
- 后续先使用Pixiv首读返回的nextIds候选，按服务端本轮有效窗口读取；单HTTP运输片≤18。若本轮23张则后续18＋5运输片合成同一轮，完全成功后原子追加并推进游标；后片失败不会丢作品／推游标，原顺序重试。自定义模式继续按所选数量揭示超返缓冲。
- 队列用完后只有明确手势／按钮才重新GET init。跨轮共享已见ID去重；相同返回显示“本轮没有新的可显示作品，再推荐一轮”，不自动循环。新轮失败保已有作品，可点“重试相关推荐”重新GET。
- 点击推荐进入的Pager快照仅继续已有候选，不因邻页／末页预加载自动重新init；新一轮由原详情的手势或按钮发起。推荐owner／账号guard保留，旧读晚回不污染新账号。
- 多图ordinary handoff是包含详情、评论和推荐的完整纵向流；到推荐才读。普通流真实向上滚回图库交界会撤回详情与推荐区到紧凑作者入口，保持评论／推荐缓存，再向下跨界复用同一个详情state。头像面板仍只到评论、无相关推荐；关闭面板回图不自动handoff或读推荐，之后要真实下滑越界才重新展示普通详情流。controller及详情在模式切换时不重建。

## 请求参数的实际边界

“由Pixiv返回”是客户端显示策略，不等于HTTP省略limit。公开固定[PixivBatchDownloader API.ts](https://github.com/xuejianxianzun/PixivBatchDownloader/blob/d808bb975b27ad03b936f6e5ffa98a3d2a915c67/src/ts/API.ts)采用init?limit=18，注释其为首屏预加载数。本次没有取得官方省略limit成功证据；网络默认null仍沿用已有limit18预载参数，完整保留实际返回，包括离线mock的23项，不宣称官方原生默认18。完整固定源码、缓存事实及mock见[网络证据](network-evidence.md)。

相同种子重新GET是否产生新作品由服务端决定，客户端不更换seed、添加未经证实的随机参数、捏造回包或反复自动重试。候选耗尽且返回重复时如实显示无新增。匿名在线取源失败，未读取真实Cookie或执行真实账号请求。

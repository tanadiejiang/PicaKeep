# PK-02：已下载目录解析修复

日期：2026-09-07。PR 分支：`codex/fix-pk02-downloaded-visibility`，基于原仓库 main，独立提交 PK-02，不依赖尚未合并的 PK-01 PR。实现和测试与本地已验证提交 `4e35797` 一致。

## 可复现的问题

本地库的 `_resolveDownloadItemDirectoryFromMetadata` 列出了目录字段、ID、清理后的名称和标题等候选，但原实现直接返回第一个非空值，不检查目录存在性。数据库保留旧目录名，而内容位于后备候选目录时，“已下载”元数据加载与完整本地库扫描都会将其认定为缺失；关闭“显示全部数据库记录”后条目消失。

另有两个路径判定缺口：Windows 驱动器绝对路径不以 `/` 开头，被再次拼接根目录；目录索引只比较路径第一层或末尾名称，可能把存在的父目录误当成完整嵌套目录存在。

## 修复行为

- 两条加载入口共用按存在性选择的候选解析；已有显式目录优先，失效时继续尝试 ID、清理后的名称和标题目录。
- 使用 `path` 库判断绝对路径、拼接和规范化。将已锁定的 `path 1.9.1` 声明为直接依赖，未升级任何依赖版本；离线 `pub get --enforce-lockfile` 通过。
- 已列出的目录索引仅用于证明根目录的直接子目录存在。Windows 使用忽略大小写的集合查询，Unix 区分大小写；普通访问的其他候选使用实际目录探测。
- 保留特权访问分支优先使用一次目录枚举、不逐本发起特权通道请求的策略。Root/Shizuku 对嵌套目录的处理需设备验收。
- 真正缺失的记录继续按设置过滤或显示占位；回收站、清空后的历史记录和同目录去重行为继续有效。
- 不自动改写用户数据库、不移动或删除下载内容。

修改文件：`local_library.dart`、`local_library_static.dart`、`local_library_scan.dart`、`pubspec.yaml`、`pubspec.lock`。
